Reverse Latent Sparse Attention

A small decoder-only language model (11,431,552 parameters) where the long-range layers do not look at every earlier token. Each key is written into a few learned anchor buckets as it appears, and each query tile reads only the buckets that look relevant. Most layers use plain sliding-window attention.

Anchors, anchor-update counter and load-balance bias are buffers, not trained parameters. Phase 3 asserts this exact count, and check_checkpoint.py rejects any checkpoint that differs.

Step 1: reverse write simulation

Each key picks its write_top_r most similar anchors. Every (block, anchor) bucket holds at most bucket_capacity keys; extra writes are dropped, lowest similarity first. This toy uses 2D angles and one block of 64 keys (real: 256 keys, 64 anchors, r=2, capacity 16).

What the real code adds

Load balancing. Eight vectorised rounds nudge a per-anchor bias so each anchor’s assignment count approaches block_size × r / n_anchors = 8 per block-anchor on average (bias clamped to ±0.5, plus a learned running load_balance_bias). Centroids. Each bucket stores the normalised mean of its retained key features. Summaries. Each retained key adds 1/r of its K and V to a per-anchor running sum, giving one cheap “average of everything in this anchor” token later.

Step 2: hierarchical read simulation

Move the query tile through the sequence. Queries are grouped in tiles of 16; the tile-start token’s index feature does the routing. Cutoff = start − 256 − 1; only blocks whose last token is ≤ cutoff are searchable.

Sequence

The five read steps

  1. Score the tile’s feature against 64 anchors, keep the top 6 (query_top_a).
  2. For each eligible block, take the centroids of those 6 anchors’ buckets. Bucket score = centroid · query + 0.1 × anchor score. Empty buckets are masked.
  3. Keep the 32 best (block, anchor) buckets across all eligible blocks (bucket_top_p).
  4. Expand to member keys: 32 × 16 = 512 candidates, in best-first order.
  5. Stable-sort deduplicate (a key written to two anchors may appear twice), then keep the first 256. The bucket score becomes an additive attention bias for those keys.

The flat_lsa ablation skips steps 1–2: it scores every anchor in every block, but still keeps only 32 buckets.

Subtracting the retrieved keys from the summary prevents counting the same token twice. All 16 queries in a tile share the retrieved set, but the local mask is per query, so causality stays exact. Tiles are processed 32 at a time, and the result is one scaled_dot_product_attention call per chunk with an additive float mask.

Design note: tokens between the last closed block and the start of the local window are not visible to either path until their block closes (up to 255 tokens). Try tile start 800 in the read tab to see the gap.

Training-time state

EMA anchors. After every forward pass, all token query features are assigned to their nearest anchor; anchors move 5% toward the cluster mean (ema_decay 0.95) and are re-normalised. Anchors with no queries are reseeded from the worst-represented queries. Routing in the current pass uses the old anchors.

Index gradients. Routing choices are hard (top-k), but the bucket score is added to the attention logits, so q_index and k_index still get gradients. Phase 2 and 3 check this.

Training and evaluation flow

Stage 1: dense warm-up

Global layers use exact causal dense attention. Sequence 512, 200 steps, peak lr 3e-4. The EMA anchors warm up from real query statistics during this stage.

Stage 2: switch to R-LSA

Same weights, global layers now use R-LSA. Sequence 1024, 200 steps, peak lr 1e-4.

Common settings: AdamW (betas 0.9/0.95, weight decay 0.1), cosine decay to 2e-5, grad clip 1.0, batch 1 × grad-accum 2, bf16 autocast, evaluation every 50 steps on 8 validation batches, final test on 8 batches. Data: a small WikiText-103 subset, 8000-token vocabulary.

Logged router health: bucket overflow rate, assignment load mean/std/max, bucket fill, active query anchors, and active EMA anchors out of 64.
