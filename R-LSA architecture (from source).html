Reverse Latent Sparse Attention (R-LSA) language model

Everything below is read from the uploaded files: config.py, model.py, attention.py, index.py and the phase scripts, plus your terminal log. The simulator in section 5 runs the index/retrieval algorithm on random unit vectors, not on trained weights.

1. Configuration (RLSAConfig as used in Phase 3/4)

Derived: head_dim = 320 / 5 = 64 (even, required by RoPE). Global layers are those with (i+1) % global_every == 0, so layers 4 and 8 (1-indexed). The other 6 are sliding-window layers. K and V use one shared head (multi-query attention).

2. Layer stack and parameter count

Per-block parameters (computed live from the config)

Not parameters: the anchor matrix [64, 32], anchor_updates and load_balance_bias [64] are registered buffers. They live in the state_dict and are updated by EMA / the balance rule, not by the optimizer. check_checkpoint.py and Phase 3 both assert the total equals 11,431,552.

3. One decoder block, step by step

Block (pre-norm, residual)

h  = LayerNorm1(x)                                  x: [B, T, 320]
a  = Attn(h)            (local or global, see below)
x  = x + a
x  = x + Dropout( W_down( SiLU(W_gate h2) * (W_up h2) ) )   h2 = LayerNorm2(x), hidden 896

Projection (HybridAttention._project)

q = W_q h  -> [B, 5, T, 64]      W_q: 320x320
k = W_k h  -> [B, 1, T, 64]      W_k: 320x64   (one K head, shared by 5 query heads)
v = W_v h  -> [B, 1, T, 64]      W_v: 320x64
local layers : q, k = RoPE(q), RoPE(k)    theta = 10000, pairs (2i, 2i+1)
global layers: NoPE (no positional rotation)
out = W_o( concat_heads(attn) )   W_o: 320x320

localSliding-window layer (6 of 8)

allowed(i, j) = 0 <= i - j <= 256        (257 keys per query)
attn = SDPA(q, k, v, attn_mask=allowed)     dropout 0.05 in training

globalGlobal layer (2 of 8) has three modes

Stage 1 / mode "dense": SDPA(q, k, v, is_causal=True) over all previous tokens.
   In training it also runs the anchor EMA on q_features[:, ::16] (every 16th position).
Stage 2 / mode "rlsa" : ReverseLatentSparseAttention (section 4).
Mode "swa"            : forced to the local sliding-window path (ablation only).

Head and loss

x = Embedding(ids) -> Dropout; 8 blocks; LayerNorm
logits = x @ E^T          (lm_head.weight is the embedding weight, tied)
loss = CrossEntropy(logits.view(-1, 8000), targets.view(-1))
init: Normal(0, 0.02) for every Linear and the Embedding

4. R-LSA inside a global layer (attention.py + index.py)

Input q [B,5,T,64], k and v [B,1,T,64]. Constants: C=64 anchors, D=32 index dim, block=256, r=2, capacity=16, a=6, p=32, budget=256, window=256, sinks=4, tile=16, tile batch=32.

Step 1: index features

q_feat = normalize( W_qi( mean_over_heads(q) ) )     W_qi: 64 -> 32, no bias
k_feat = normalize( W_ki( k ) )                       W_ki: 64 -> 32, no bias

Step 2: reverse write (build_reverse_index)

Only complete blocks are indexed: n_blocks = floor(T / 256). Each key chooses its anchors, so buckets are written from the key side.

sim[t, c] = k_feat[t] . anchor[c]                       per block: [256, 64]
target    = block * r / C = 256 * 2 / 64 = 8            (the "load 8.0" in your log)
bias      = load_balance_bias                           (buffer, [64])
repeat 8 times:
    top   = topk_r( sim + bias )
    hist[c] = number of assignments to anchor c in this block
    bias  = clamp( bias + 0.01 * (target - hist) / max(target, 1), -0.5, 0.5 )
final top_ids = topk_r( sim + bias )                    each key written to r=2 anchors
capacity: for each (block, anchor) keep the 16 members with highest raw sim
overflow  = sum( max(assigned - 16, 0) )
centroid[block, anchor] = normalize( mean of retained k_feat )   (zeros if bucket empty)
mass weight per posting = 1 / r
S_k, S_v[block, anchor] = sum of weight * k (or v) over retained members
mass[block, anchor]     = sum of weights
prefix sums over the block axis give "all closed blocks" in O(1)

token_retained_anchors [B,T,r] records which of a token’s r writes survived the capacity clip, so retrieved keys can later be removed from the summaries.

Step 3: query tiles and causal cutoff

tiles      = ceil(T / 16);  tile j starts at s = 16 j
query feat = q_feat[:, s]            (the first query of the tile routes for all 16)
cutoff     = s - local_window - 1 = s - 257
eligible   = clamp( floor((cutoff + 1) / 256), 0, n_blocks )   closed blocks only

Step 4: hierarchical read (retrieve_remote_keys_batched)

anchor_score = q_tile . anchor^T ;   take top a=6 anchors
bucket_score[block, a] = centroid[block, a] . q_tile + 0.1 * anchor_score[a]
masked to -inf if bucket empty or block newer than cutoff
take top p = min(32, eligible * 6) buckets over (block, anchor)
candidates = their members, in best-first order      (up to 32 * 16 = 512)
each candidate carries bias = its bucket_score
stable first-occurrence dedup (sort-based), keep first 256 -> remote_ids [B, tiles, 256], -1 padded

With T=1024 only blocks 0 and 1 can ever be eligible (tile start 768 gives cutoff 511, floor(512/256) = 2), so p is at most 12 buckets and at most 192 candidates. The 256 budget cannot fill at this length. Your log shows 24.3 valid remote keys per tile on average at the end of Stage 2.

Step 5: anchor summary tokens

for each anchor c, over eligible closed blocks:  Sk, Sv, mass from the prefix sums
subtract the retrieved keys so nothing is counted twice:
    w[n, c]  = (1/r) for each retained write of retrieved key n to anchor c
    mass'    = max(mass - sum_n w, 0)
    Sk'      = Sk - sum_n w * k_n          Sv' likewise
summary_k = Sk' / max(mass', 1e-6) ;  summary_v = Sv' / max(mass', 1e-6)
valid if mass' > 0 ;  attention logit bias = log(max(mass', 1e-6))

Step 6: key layout and mask per tile

K = [ 4 sinks | 256 remote | 64 summaries | local: 272 positions s-256 ... s+15 ]   total 596 slots
sinks    : learned sink_k, sink_v [5, 4, 64], bias 0, always allowed
remote   : valid where id >= 0, bias = bucket_score
summary  : valid where mass' > 0, bias = log(mass')
local    : allowed if key_pos <= query_pos, key_pos >= 0 (causal inside the tile)
logits = Q K^T / sqrt(64) + bias ;  masked -inf ;  softmax ;  @ V
executed as F.scaled_dot_product_attention(attn_mask=additive, is_causal=False)

Step 7: state updates in training (after the forward pass)

anchors (spherical EMA k-means on the sampled tile queries):
    winner = argmax(q . anchor) ;  centre_c = normalize(mean of its queries)
    anchor_c = normalize( 0.95 * anchor_c + 0.05 * centre_c )
    anchors with no queries are reseeded from the least-represented queries
load_balance_bias += 0.02 * clamp( (target - observed_mean_load) / max(target,1), -2, 2 )
    then clamped to [-1, 1]
Index gradients flow only through the bucket-score biases on remote keys.

Readings that follow directly from these numbers: all five modes differ by under 0.001 in loss, so at this training length the model is not using long-range retrieval in a way these ablations can detect (validation loss is still near 6.5, i.e. the model is early in training). R-LSA is about 2.4x slower than dense at 1024 tokens, which is expected when the dense path is one fused call over a short sequence and R-LSA adds index build, top-k, sort-based dedup and gathers. A cost advantage can only appear at lengths where dense attention cost dominates. The report’s own notes state this is a checkpoint ablation, not matched retraining, and does not measure decode.
